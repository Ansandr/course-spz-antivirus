# AntivirusMVP

Курсовий проєкт з дисципліни «Системне програмне забезпечення».

Мета проєкту: реалізувати мінімально життєздатний антивірусний застосунок для Windows з GUI на Qt, який вміє сканувати файли за сигнатурами, працювати з карантином, формувати звіти.

## Основні можливості

- Рекурсивне сканування директорій за MD5-сигнатурами.
- Виявлення EICAR тестового файлу.
- Асинхронне сканування в окремому потоці (UI не блокується).
- Перегляд активних процесів із позначенням підозрілих шляхів.
- Ізоляція, відновлення та видалення файлів у карантині.
- Автоматичне формування звіту після сканування.
- Перегляд журналу подій та редагування whitelist.
- Unit-тести (Qt Test) для ключових класів.

## Технології

- C++17
- Qt 6 (Core, Gui, Widgets, Test)
- CMake
- MSVC (Visual Studio 2022)
- GitHub Actions (CI)

## Структура репозиторію

- `src/` - вихідний код застосунку та ядра.
- `tests/` - unit-тести Qt Test.
- `docs/` - документація проєкту (пояснення, user stories, тест-кейси).
- `signatures.db` - база сигнатур (містить EICAR сигнатуру).
- `.github/workflows/` - CI workflow для збірки та перевірок.

## Вимоги до середовища

- Windows 10/11
- CMake >= 3.20
- Qt 6.x
- Visual Studio 2022 (MSVC)

## Збірка та запуск

```powershell
cmake -S . -B build
cmake --build build --config Debug
.\build\Debug\AntivirusMVP.exe
```

## Запуск тестів

```powershell
cmake -S . -B build
cmake --build build --config Debug
ctest --test-dir build -C Debug --output-on-failure
```

Доступні окремі тести:

- `test_signaturedb`
- `test_scanner`
- `test_quarantine`

## Робота з GitHub: Issues та Actions

### Issues

Вкладка Issues використовується для:

- ведення User Stories;
- постановки задач по спринтах;
- фіксації дефектів (Bug Reports);
- відстеження прогресу через статуси та PR-посилання.

Рекомендація: для кожної історії/дефекту створювати окремий Issue і закривати його через Pull Request.

### Actions

Вкладка Actions використовується для CI:

- автоматична збірка проєкту при PR;
- перевірка, що зміни компілюються;
- формування артефактів збірки (за налаштованим workflow).

Перед merge перевіряйте, що workflow завершився успішно (усі jobs у статусі Passed).
