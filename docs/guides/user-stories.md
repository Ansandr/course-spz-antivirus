# User Stories — Antivirus MVP

> Цей файл містить всі User Stories проєкту, оформлені для GitHub Issues.  
> Кожна story — окремий Issue. Після створення Issue закрийте його через PR з відповідної `feature/`-гілки.

## Sprint 1 — Etap 1: Ядро системи (6 SP)

---

### [US-01] Ініціалізація Qt-проєкту та CMake

**Labels:** `setup` `sprint-1`  
**Story Points:** 1  
**Гілка:** `feature/project-setup`

**Як** розробник, **я хочу** мати правильно налаштований Qt 6 C++ проєкт із CMake та структурою директорій, **щоб** одразу розпочати реалізацію класів.

**Критерії виконання:**
- [ ] Створено `CMakeLists.txt` зі статичною бібліотекою `antivirus_core` та виконуваним файлом `AntivirusMVP`
- [ ] Структура директорій: `src/`, `docs/`, `signatures.db`
- [ ] Проєкт успішно компілюється (порожній `main.cpp`)
- [ ] Налаштовано `.gitignore` для Qt/CMake/MSVC/MinGW артефактів
- [ ] Перший коміт у гілку `feature/project-setup`, PR → `develop`

---

### [US-02] Клас Logger — потоко-безпечне журналювання

**Labels:** `core` `sprint-1`  
**Story Points:** 1  
**Гілка:** `feature/logger`

**Як** система, **я хочу** записувати всі події до `antivirus.log` з часовими мітками та рівнями, **щоб** адміністратор міг аудитувати операції програми.

**Критерії виконання:**
- [ ] Клас `Logger` реалізований як Singleton (`static Logger* instance()`)
- [ ] Підтримуються рівні: `INFO`, `WARNING`, `ERROR`
- [ ] Запис захищений `QMutex` (thread-safe для Scanner у QThread)
- [ ] Файл відкривається у `%APPDATA%/AntivirusMVP/antivirus.log`
- [ ] Формат рядка: `[yyyy-MM-dd HH:mm:ss] [РІВЕНЬ] повідомлення`
- [ ] PR → `develop` після проходження ручного тесту

---

### [US-03] Клас SignatureDB — завантаження бази сигнатур

**Labels:** `core` `sprint-1`  
**Story Points:** 1  
**Гілка:** `feature/signaturedb`

**Як** сканер, **я хочу** завантажувати MD5-хеші з `signatures.db` у `QHash`, **щоб** виконувати пошук загроз за O(1).

**Критерії виконання:**
- [ ] Клас `SignatureDB` завантажує файл формату `MD5_HEX  ThreatName` (пробіл/таб як роздільник)
- [ ] Рядки з `#` та порожні рядки ігноруються
- [ ] Метод `lookup(md5)` повертає назву загрози або порожній `QString`
- [ ] `signatures.db` містить хеш EICAR-тест-файлу: `44d88612fea8a8f36de82e1278abb02f`
- [ ] Метод `count()` повертає кількість завантажених записів

### [US-04] Клас Scanner — рекурсивний обхід та MD5

**Labels:** `core` `sprint-1`  
**Story Points:** 2  
**Гілка:** `feature/scanner`

**Як** користувач, **я хочу** щоб програма рекурсивно перевіряла файли директорії порівнюючи їх MD5 з базою, **щоб** виявляти відомі загрози.

**Критерії виконання:**
- [ ] Клас `Scanner : public QObject` з методом `run()` (Qt slot для `QThread`)
- [ ] Рекурсивний обхід через `QDirIterator::Subdirectories`
- [ ] MD5 обчислюється через `QCryptographicHash::Md5`
- [ ] Файли з whitelist пропускаються (порівняння `startsWith`)
- [ ] Сигнали: `progress(int current, int total)`, `threatFound(QString, QString, QString)`, `finished(int, int)`
- [ ] Недоступні файли (locked) логуються як WARNING, не спричиняють краш
- [ ] `stop()` через `std::atomic<bool>` коректно зупиняє ітерацію

### [US-05] Консольна верифікація виявлення EICAR

**Labels:** `testing` `sprint-1`  
**Story Points:** 1  
**Гілка:** `feature/scanner` (продовження)

**Як** розробник, **я хочу** перевірити виявлення EICAR у консольному режимі до інтеграції GUI, **щоб** підтвердити коректність ядра.

**Критерії виконання:**
- [ ] Файл `eicar_test.txt` з EICAR-рядком збережено у тимчасову директорію
- [ ] `main.cpp` у debug-режимі синхронно запускає `Scanner` та виводить результат
- [ ] Лог підтверджує виявлення: `[WARNING] THREAT [EICAR-Standard-Test-File]`
- [ ] Файл `eicar_test.txt` **не** потрапляє до репозиторію (`.gitignore`)

**Гілка:** `feature/mainwindow-skeleton`

### [US-07] Вкладка «Сканування» з QThread та QProgressBar

**Labels:** `gui` `sprint-2`  
**Story Points:** 2  
**Гілка:** `feature/scan-tab`

**Як** користувач, **я хочу** обрати директорію, запустити сканування та бачити результати у реальному часі, **щоб** знати про знайдені загрози.

**Критерії виконання:**
- [ ] Кнопка «Обрати…» відкриває `QFileDialog::getExistingDirectory`
- [ ] Кнопки «Розпочати сканування» та «Зупинити» (кнопка вимикається під час сканування)
- [ ] `QProgressBar` показує прогрес (поточний / загальний файли)
- [ ] `QTableWidget` з колонками: Файл / Статус / Загроза
- [ ] Рядки з загрозами підсвічуються червоним (`setForeground(Qt::red)`)
- [ ] Сканування виконується у `QThread` — UI залишається реагуючим
- [ ] Кнопка «Відкрити звіт» активується після завершення

### [US-08] Клас ProcessList + вкладка «Процеси»

**Labels:** `core` `gui` `sprint-2`  
**Story Points:** 2  
**Гілка:** `feature/processlist`

**Як** користувач, **я хочу** бачити список активних процесів з PID, ім'ям та шляхом, **щоб** виявляти підозрілу активність.

**Критерії виконання:**
- [ ] Клас `ProcessList` з методом `snapshot() → QVector<ProcessInfo>`
- [ ] Використовує `CreateToolhelp32Snapshot()` + `QueryFullProcessImageNameW()`
- [ ] `ProcessInfo`: `uint32_t pid`, `QString name`, `QString executablePath`, `bool isSuspicious`
- [ ] Підозрілі шляхи (`\Temp\`, `\tmp\`, `\Downloads\`) підсвічуються червоним
- [ ] `ERROR_ACCESS_DENIED` → поле `executablePath = "N/A"` (без краша)
- [ ] Кнопка «Оновити список» оновлює таблицю

---

### [US-09] Клас Quarantine + вкладка «Карантин»

**Labels:** `core` `gui` `sprint-2`  
**Story Points:** 2  
**Гілка:** `feature/quarantine`

**Як** користувач, **я хочу** переміщувати загрози до ізольованої директорії та відновлювати їх, **щоб** безпечно управляти підозрілими файлами.

**Критерії виконання:**
- [ ] Клас `Quarantine(quarantineDir)` з методами `isolate()`, `restore(index)`, `removeEntry(index)`
- [ ] Ізоляція: `QFile::rename()` → `%APPDATA%/AntivirusMVP/Quarantine/<name>_<timestamp>`
- [ ] Метадані зберігаються у `quarantine_index.json` (originalPath, date, threatName)
- [ ] Перевірка вільного місця: < 100 МБ → повернути `false`
- [ ] Кнопки «Відновити» та «Видалити назавжди» у вкладці Карантин

### [US-10] Клас ReportWriter + автозбереження звіту

**Labels:** `core` `sprint-3`  
**Story Points:** 1  
**Гілка:** `feature/reports`

**Як** користувач, **я хочу** щоб після сканування автоматично зберігався звіт у файл, **щоб** я міг переглянути результати пізніше.

- [ ] Вміст: дата, директорія, кількість файлів/загроз, список загроз з MD5
- [ ] Кнопка «Відкрити звіт» → `QDesktopServices::openUrl()`

**Story Points:** 1  
**Гілка:** `feature/log-settings-tabs`

### [US-12] Unit-тести Qt Test

**Labels:** `testing` `sprint-3`  
**Story Points:** 1  
**Гілка:** `feature/unit-tests`

**Як** розробник, **я хочу** мати автоматичні unit-тести для ключових класів, **щоб** підтвердити коректність реалізації.

**Критерії виконання:**
- [ ] Тести `SignatureDB`: `load()` → `true`; `lookup(EICAR_MD5)` → `"EICAR-Standard-Test-File"`; `lookup(unknown)` → `""`
- [ ] Тести `Scanner`: сканування директорії з EICAR-файлом → сигнал `threatFound` спрацьовує
- [ ] Тести `Quarantine`: `isolate()` переміщує файл; `restore()` повертає файл на місце
- [ ] Всі тести проходять: `ctest --output-on-failure`
